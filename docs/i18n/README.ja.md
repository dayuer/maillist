**Nibwire** は、オープンソースでセルフホスト型のニュースレター／メーリングリスト・エンジンです。Go のバイナリ 1 つで動作し、購読者、各号の内容、配信履歴、分析データはすべて 1 つの SQLite ファイルに保存されます。コマンドラインから操作することも、**Model Context Protocol（MCP）** を通じて AI エージェントに任せることもできます。エージェントの操作は、どんなプロンプトでも外せない安全柵の中に収まります。

管理画面のお守りも、データベースクラスタやキャッシュ、キューの運用も不要です。リストもデータもサーバーも、あなたのものです。

- 🤖 **エージェント対応**：27 個の MCP ツール、権限を絞った認証情報、日次の送信枠、完全な監査ログ
- 📦 **バイナリ 1 つ、ファイル 1 つ**：ニュースレターのすべてが 1 つのデータベースにあり、コマンド 1 つでバックアップ
- 🛡️ **設計そのものが安全**：二重送信、配信済みの号の再送、配信停止した人への送信は起こりえません
- ⚡ **速く、行儀がよい**：並行配信しつつ、配信事業者の上限に合わせて自動で速度を調整
- 💸 **低コストで運用**：いちばん安い VPS でも余裕で動作
- 📬 **読者に必要なものはすべて**：ワンクリック配信停止、ダブルオプトイン、公開アーカイブ、独自ドメイン
- 🔓 **オープンソース**：AGPL-3.0、商用ライセンスもあり

## なぜ Nibwire なのか

**人だけでなく、エージェントのために作られている**<br>
下書き、チェック、テスト送信、予約、レポートの確認まで、すべてのステップが MCP ツールです。危険な操作は「推奨しない」のではなく、構造的に不可能です。削除ツールは存在せず、送信前チェックは飛ばせず、認証情報に与えた送信枠も超えられません。

**運用は驚くほどシンプル**<br>
アーカイブの配信、開封・クリック計測、予約、送信、バウンス処理を 1 つのプロセスがこなし、データはすべて 1 つの SQLite ファイルに入っています。アップグレードは新しいイメージを pull するだけ、バックアップは `nibwire db backup` だけです。

**常に守られる 5 つの保証**
1. 配信停止・バウンス・苦情のあったアドレスには決して送信しない。
2. 送信前チェックを通らない号は送信できない。
3. 送信済みの号を再送することはできない。
4. 1 日の送信量は上限を超えない（今日一時停止して明日再開しても同じ）。
5. 送信中にサーバーが落ちても、同じメールが二重に届くことはない。

**速く、良き市民として**<br>
並行配信を行い、配信事業者がその時点で許す速度に自動で合わせます。負荷試験では 20,000 通を約 45 秒で、重複ゼロ・失敗ゼロで配信しました。その日の残り枠に収まらない送信は、途中で止まるのではなく開始前に断ります。

**リストを健全に保つ**<br>
バウンスと苦情は自動で抑止リストに入り、すべてのニュースレター間で共有されます。バウンス率や苦情率が安全な水準を超えると送信は自動で一時停止します。任意のリスト整理機能は、非アクティブな読者に「最後のお知らせ」を送ってから整理します。

**読者体験も万全**<br>
ワンクリック配信停止（RFC 8058）、任意のダブルオプトインとウェルカムメール、公開の購読フォーム、号ごとのページ・著者ページ・サイトマップを備えた公開アーカイブ（独自ドメインにも対応）を提供します。開封・クリック計測はセキュリティスキャナーを除外するので、数字に意味があります。

## クイックスタート

ノート PC で数分あれば全体を試せます。内蔵のローカル受信先を使うので、アカウントや認証情報は不要で、メールが外に出ることもありません。

```bash
git clone https://github.com/dayuer/nibwire.git
cd nibwire
KEEP=1 scripts/compose-smoke.sh
```
